# COUNTERSIGN — Proof Before Permission

## Role
COUNTERSIGN is **not** the visible product. It governs actions generated by RELAY or any routed specialist agent.

## Core question
> What must be true for this proposed action to be justified right now?

## Action tiers

### Tier 0 — Assist freely
- explain
- enlarge
- summarize
- caption
- search
- draft
- create reminder

Default: auto-execute.

### Tier 1 — Reversible / low consequence
- add calendar event
- save note
- draft message
- request appointment availability

Default: execute if user policy allows; otherwise light confirmation.

### Tier 2 — Consequential
- send message
- upload personal document
- submit form
- book service
- cancel appointment

Default: explain + explicit confirmation.

### Tier 3 — High consequence
- send money
- change banking details
- sign legal agreement
- reveal SSN
- release medical record
- change benefits

Default: strong verification + explicit confirmation, or block in MVP.

## Proof obligations
For `submit_registration()`:
- intended destination verified
- user requested/accepted task
- fields come from known sources or user input
- sensitive fields enumerated
- no unresolved contradiction
- final payload shown to user

## Verdicts
- `ALLOW`
- `ALLOW_WITH_NOTICE`
- `ASK_USER`
- `HOLD_UNRESOLVED`
- `DENY_POLICY`

## Action proposal
```json
{
  "action_id": "a_123",
  "action_type": "submit_form",
  "target": "demo-clinic",
  "payload_summary": "registration",
  "risk_tier": 2,
  "reversible": false,
  "proof_obligations": []
}
```

## Decision receipt
For Tier 2+ store:
- proposed action
- source context
- user confirmation
- key evidence
- execution time
- result
- follow-up

## Anti-pattern
Do not make COUNTERSIGN:
> “ask a second LLM whether the first LLM is right.”

Prefer deterministic checks, external state, connector responses, and user confirmation.
