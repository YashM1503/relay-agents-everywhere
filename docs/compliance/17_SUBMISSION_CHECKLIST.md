# Submission Checklist

## Product
- [ ] one user
- [ ] one problem
- [ ] one complete interaction
- [ ] environment context visible
- [ ] agent takes action
- [ ] human control visible
- [ ] outcome visible
- [ ] failure/cancel works

## Technical
- [ ] repo builds cleanly
- [ ] env vars documented
- [ ] demo data synthetic
- [ ] no secrets committed
- [ ] providers marked live/mock
- [ ] dependencies documented
- [ ] README says what was built during hackathon

## Demo
- [ ] <2 min
- [ ] no architecture lecture before user problem
- [ ] no fragile live dependency if avoidable
- [ ] backup video
- [ ] exact demo passes 3 times

## Business
- [ ] user clear
- [ ] buyer clear
- [ ] measurable value clear
- [ ] why phone/environment matters clear
- [ ] autonomy/privacy critique addressed
- [ ] expansion path concise

## Best hackathon sentence
> “The agent is useful because it is present during the real interaction, with the user’s chosen context and permissions — not because the user stopped everything to open a chatbot.”
